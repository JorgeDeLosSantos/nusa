# NuSA 0.4.0 manual acceptance

This checklist complements CI. It records the small set of release checks that
are valuable to run in real user environments before promoting
`0.4.0.dev0` to `0.4.0`.

## Already covered automatically

- [x] Python 3.10 / 3.12 / 3.14 test suite.
- [x] Installation smoke tests on Ubuntu, Windows and macOS runners.
- [x] Wheel and source-distribution build/install smoke tests.
- [x] Sphinx documentation build.
- [x] Real Gmsh geometry/mesh integration on Ubuntu.
- [x] End-to-end real-Gmsh path: geometry -> triangle mesh ->
      `LinearTriangleModel` -> solve -> recovered von Mises stress.
- [x] Release-acceptance contract for all five current element families.

These checks reduce risk but do not replace a short manual run in the environments
most likely to expose installation or notebook-specific friction.

## Windows manual acceptance

Run from a clean shell/environment on the maintainer's normal Windows machine.

### 1. Clean package installation

```powershell
py -m venv .venv-nusa-040
.\.venv-nusa-040\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install "nusa @ git+https://github.com/JorgeDeLosSantos/nusa.git@develop"
python -c "import nusa; print(nusa.__version__)"
```

Expected before the final release: `0.4.0.dev0`.

- [x] Clean installation completes without manual dependency repair.
- [x] `import nusa` succeeds.
- [x] Reported version is the expected development version.

Manual result (Windows, Python 3.12): installation from `develop` resolved to
commit `52bd3412153241dd39ede8fa31b0473418f9af21` and installed
`nusa-0.4.0.dev0` successfully. When testing an installed package, run the
import check outside the NuSA source checkout; otherwise the local `nusa/`
package can shadow the installed environment on `sys.path`.

### 2. Core solve

```powershell
python -c "from nusa import Node,Bar,BarModel; n1=Node((0,0)); n2=Node((1,0)); m=BarModel(); m.add_nodes([n1,n2]); m.add_element(Bar((n1,n2),E=200e9,A=1e-4)); m.add_constraint(n1,ux=0); m.add_force(n2,(1000,)); r=m.solve(); print(r.displacement(n2)); print(r.reaction(n1))"
```

- [x] Solve succeeds.
- [x] Displacement and reaction are finite.
- [x] No obvious regression in console output or exceptions.

Manual result: the one-meter bar returned `{'ux': 5e-05}` at the loaded node
and `{'fx': -1000.0}` at the constrained node, matching the expected values.

### 3. Gmsh visibility

Use the same environment intended for NuSA mesh generation.

```powershell
gmsh --version
```

If Gmsh comes from conda, also verify it from that exact environment. NuSA
supports `.bat` / `.cmd` launchers through `cmd.exe`, but environment mismatch
between a conda Gmsh launcher and an unrelated `venv` can still break Gmsh itself.

- [x] `gmsh --version` succeeds in the environment used with NuSA.

Manual result: the existing Anaconda `base` Gmsh launcher was incomplete
(`ModuleNotFoundError: No module named 'gmsh'`). Installing `gmsh==4.15.2`
inside the clean NuSA virtual environment created a working local launcher;
both `gmsh --version` and `python -c "import gmsh; print(gmsh.__version__)"`
reported `4.15.2`.

### 4. Mesh generation

```powershell
python -c "from nusa.mesh import Modeler; m=Modeler(); m.add_rectangle((0,0),(0.2,0.1),esize=0.05); nc,ec=m.generate_mesh(); print(nc.shape,ec.shape)"
```

- [x] Mesh generation succeeds.
- [x] Connectivity is triangular (`ec.shape[1] == 3`).

Manual result: the Windows environment generated a mesh with `18` nodes and
`22` three-node triangles (`nc.shape == (18, 3)`,
`ec.shape == (22, 3)`).

## Release gate

Proceed to `release/0.4.0` when:

- [x] Windows manual acceptance is complete.
- [ ] Google Colab manual acceptance is complete.
- [ ] No release-blocking documentation/API issue was found during those runs.
- [ ] `develop` CI remains green after any resulting fixes.

If a problem is found, fix it on `develop`, rerun the relevant manual check, and
only then prepare the final release branch.
